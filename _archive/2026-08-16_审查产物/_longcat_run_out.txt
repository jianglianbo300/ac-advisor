def dehumid_duty(temp, hum=None):
    if temp is None:
        base = DEHUMID_DUTY
    elif temp >= 26:
        base = DEHUMID_DUTY
    elif temp <= TEMP_ABSOLUTE_FLOOR:
        base = 0.25
    else:
        base = 0.25 + (DEHUMID_DUTY - 0.25) * (temp - TEMP_ABSOLUTE_FLOOR) / (26 - TEMP_ABSOLUTE_FLOOR)
    if hum is not None:
        if hum >= 85:
            factor = 1.10
        elif hum <= 60:
            factor = 0.70
        else:
            factor = 0.70 + 0.40 * (hum - 60) / 25.0
        base *= factor
    return base

```python
def minutes_since(ts_str: str | None) -> float | None:
    if not ts_str:
        return None
    try:
        then = datetime.fromisoformat(ts_str)
        now = datetime.now(tz=then.tzinfo if then.tzinfo else None)
        return (now - then).total_seconds() / 60.0
    except Exception:
        return None
```
- 时区处理：如果 ts_str 有时区信息，now 也使用相同的时区；如果 ts_str 没有时区，now 也没有时区

def apply_and_commit(new_mode, target_temp, state, now_ts=None, meta=None):
    if now_ts is None:
        now_ts = datetime.now().isoformat(timespec="seconds")
    ctrl = ac_apply(new_mode, target_temp)
    if ctrl["status"] == "failed":
        save_state(state)
        return ctrl
    real = verify_socket()
    if real is None:
        ctrl = {"status": "failed", "action": ctrl.get("action", ""), "reason": "verify_unreachable"}
        save_state(state)
        return ctrl
    contradict = apply_state_from_verify(state, new_mode, real, now_ts)

        ctrl = {"status": "failed", "action": ctrl.get("action", ""),
                "reason": "verify_on_after_off" if real == "on" else "verify_off_after_on"}
    if meta and not contradict:
        for k, v in meta.items():
            state[k] = v
    if not contradict and target_temp is not None:
        state["target_temp"] = target_temp
    save_state(state)
    return ctrl

**问题7：kWh积分**

```python
def update_kwh(state, now_ts, load_power):
    """梯形积分更新 estimated_kWh。"""
    prev_power = state.get("_prev_power")
    prev_ts = state.get("_prev_kwh_ts")
    kwh = state.get("estimated_kwh", 0.0)
    if prev_power is not None and prev_ts is not None and load_power is not None:
        try:
            dt_hours = (datetime.fromisoformat(now_ts) - datetime.fromisoformat(prev_ts)).total_seconds() / 3600
            if dt_hours > 0 and dt_hours < 1:  # 防止异常间隔
                avg_power = (prev_power + load_power) / 2.0
                kwh += avg_power * dt_hours / 1000.0
        except Exception:
            pass
    state["estimated_kwh"] = round(kwh, 4)
    if load_power is not None:
        state["_prev_power"] = load_power
        state["_prev_kwh_ts"] = now_ts
```

这里有个问题：当`load_power` is None时，不更新锚点。但注释说"sensor unknown 不覆盖锚点"。这是对的。

但问题：如果`load_power` is None，不积分，但`estimated_kwh`仍然被更新为`round(kwh, 4)`。这没问题，因为kwh没变。

但`_prev_power`和`_prev_kwh_ts`不更新，这意味着下次恢复时，会用旧的锚点时间，导致积分间隔变大。

例如：
- 22:00: power=1100, kwh=0
- 22:10: power=1100, kwh=0.1833
- 22:20: power=None, kwh=0.1833（不积分，锚点保留在22:10）
- 22:30: power=50, kwh=0.1833 + (1100+50)/2 * 20min / 1000 = 0.1833 + 0.1917 = 0.375

但22:10到22:30的20分钟内，实际功率可能是0（空调关了），但代码会按1100→50积分，导致kWh被高估。

这是个问题。当sensor unknown时，应该假设功率为0或者不积分，但恢复时应该用当前时间作为新的锚点时间，而不是用旧锚点。

**问题8：decide中的无效判断**

```python
# 无效（Tier 4）：压缩机实际跑了 60min 以上 RH 降幅不足 → 立即关掉（不空耗）
if (comp_min is not None and comp_min >= DEHUMID_STALL_MIN
        and delta_rh_60min is not None
        and delta_rh_60min > -DEHUMID_STALL_RH_BAND):
    return ("off", None, f"压缩机跑了{int(comp_min)}分钟湿度降幅不足，判定无效空耗关机")
```

这里`delta_rh_60min > -1.5`表示60分钟内RH降幅不足1.5%（即delta_rh_60min > -1.5）。但注释说"湿度上涨=环境在加湿，不该停；只有下降不足才算无效"。

如果`delta_rh_60min`是正的（湿度上涨），那`delta_rh_60min > -1.5`为True，会触发关机。这与注释矛盾。

实际上，`delta_rh_60min`应该是负值表示湿度下降。如果`delta_rh_60min = -0.5`（下降0.5%），那`-0.5 > -1.5`为True，触发关机。这是对的。

如果`delta_rh_60min = 1.0`（上涨1%），那`1.0 > -1.5`为True，也会触发关机。这与注释"湿度上涨不该停"矛盾。

所以条件应该是`delta_rh_60min > -1.5 and delta_rh_60min < 0`，或者更准确地说`-1.5 < delta_rh_60min < 0`。

但代码中只检查了`delta_rh_60min > -1.5`，没有检查`delta_rh_60min < 0`。

**问题9：虚拟变频恢复条件**

```python
# v8.9 降温补偿（Laguna 交叉审查）：虚拟变频升温后湿度回升 → 降回重启
if (hum >= VIRTUAL_INV_RECOVER_RH
        and current_target > A.TEMP_ABSOLUTE_FLOOR + 1
        and not in_cooldown):
    return ("cooling", 24,
            f"升温缓除后湿度回升到{hum:.0f}%，降回24度继续除湿")
```

这里`VIRTUAL_INV_RECOVER_RH = 62`，但注释说"填补58%~66%之间的无人区"。如果湿度>=62%就降回24度，那62%确实在58-66之间。

但问题：这个条件在假运行分支中，当`compressor == "fan_only"`时触发。但如果压缩机在运行（`compressor == "compressor"`），这个条件不会检查。

在压缩机运行分支中，有：
```python
# 虚拟变频（v8.8）：湿度接近达标（≤58）且已跑够 MIN_RUN → 升温降负载缓除
if (hum <= VIRTUAL_INV_APPROACH_RH
        and comp_min is not None and comp_min >= A.MIN_RUN
        and current_target is not None and current_target < VIRTUAL_INV_MAX_TARGET
        and minutes_since_last_adjust is not None
        and minutes_since_last_adjust >= DEHUMID_ADJUST_COOLDOWN):
    new_target = min(VIRTUAL_INV_MAX_TARGET, current_target + 1)
    return ("cooling", new_target,
            f"湿度近达标（{hum:.0f}%），目标升1度到{new_target}度缓除防过冷")
```

这里`VIRTUAL_INV_APPROACH_RH = 58`，`VIRTUAL_INV_RECOVER_RH = 62`。

如果湿度在58-62之间，虚拟变频不触发（因为>58），恢复也不触发（因为<62）。这就是"无人区"。

但注释说"填补58%~66%之间的无人区"，而代码中恢复条件是>=62，所以58-62之间确实无人覆盖。

等等，让我重新看注释：
"v8.9 降温补偿（Laguna 交叉审查）：虚拟变频升温后湿度回升 → 降回重启
填补 58%~66% 之间的"无人区"（假运行检测只覆盖 >66%）"

注释说假运行检测只覆盖>66%，但代码中假运行检测是`hum > DEHUMID_LOW_EFF_RH`即`hum > 66`。所以假运行检测覆盖>66%。

虚拟变频恢复条件是`hum >= 62`，所以覆盖>=62%。

那62-66%之间呢？假运行检测覆盖>66%，恢复覆盖>=62%，所以62-66%被恢复覆盖。

但注释说"填补58%~66%之间的无人区"，而代码中恢复条件是>=62，所以58-62之间还是无人区。

这确实是个问题。如果湿度在58-62之间，虚拟变频不触发（>58），恢复不触发（<62），假运行检测不触发（<=66）。这就是无人区。
